Electron Architecture & IPC Communication PlanThis document outlines the planned architecture for the Harness Monitor widget using Electron, specifically detailing how the Main Process and Renderer Process (React UI) will interact.1. Application Window Configuration (Main Process)To achieve the macOS "widget" look depicted in the prototype, the BrowserWindow must be configured with specific flags:frame: false - Hides standard OS title bar and window controls.transparent: true - Allows the CSS rgba backgrounds and backdrop filters to composite with the desktop.vibrancy: 'sidebar' | 'hud' (macOS only) - Alternative to pure CSS blur, invoking native macOS window vibrancy.alwaysOnTop: true (Toggled via settings).skipTaskbar: true - Ensures it behaves like a widget/tray app rather than a standard open window.resizable: false - Locks width to 340px.2. IPC Channels (Main <-> Renderer)The application requires strict separation between the Node.js environment (Main) and the UI (Renderer). All communication will happen via contextBridge and ipcMain/ipcRenderer.Channel 1: Window & System ControlsHandles the physical behavior of the application window.IPC_WINDOW_PIN: Renderer tells Main to toggle setAlwaysOnTop(boolean).IPC_APP_QUIT: Renderer tells Main to execute app.quit().IPC_TOGGLE_LOGIN_START: Renderer tells Main to configure OS startup registry/login items.Channel 2: Tray Menu IntegrationWhile the HTML prototype built a "mock" tray menu, in Electron, this must be handled natively by the Main process using the Tray module.IPC_UPDATE_TRAY_BADGE: Renderer sends a number (e.g., pending approvals count). Main updates the native Tray icon to show a red dot/number.Note: The UI context menu drawn in HTML should ideally be moved to a native Electron Menu triggered by the Tray, OR the Tray click should simply show/hide the frameless BrowserWindow at the cursor position.Channel 3: Agent Orchestration (Core Functionality)Handles interactions between the UI and the underlying CLI processes (Claude Code, OpenClaw).IPC_FETCH_SESSIONS (Invoke/Handle): UI requests current running agents and their states.IPC_SESSION_UPDATE (Main to Renderer): Real-time push of telemetry (Context usage %, memory usage).IPC_ACTION_REQUIRED (Main to Renderer): Main process detects an agent requires human intervention (e.g., sudo command). Pushes data to UI to trigger the "Wait Approval" state.IPC_APPROVE_ACTION (Renderer to Main): UI sends approval boolean back to the specific agent process ID.IPC_OPEN_TERMINAL (Renderer to Main): UI requests to open the host OS terminal (e.g., iTerm, Terminal.app, or Windows Terminal) attached to the specific agent's session.Channel 4: API & Telemetry DataIPC_FETCH_USAGE (Invoke/Handle): Fetches local token usage databases or makes secure API calls to a central gateway to retrieve balance and token trends.3. Preload Script (preload.js) ExposureThe contextBridge should expose a safe API to the React frontend:contextBridge.exposeInMainWorld('electronAPI', {
  // Window controls
  quitApp: () => ipcRenderer.send('app-quit'),
  togglePin: (pinned) => ipcRenderer.send('window-pin', pinned),
  
  // Agent Data
  onSessionUpdate: (callback) => ipcRenderer.on('session-update', callback),
  onActionRequired: (callback) => ipcRenderer.on('action-required', callback),
  respondToAction: (sessionId, approved) => ipcRenderer.send('action-response', { sessionId, approved }),
  openTerminal: (sessionId) => ipcRenderer.send('open-terminal', sessionId),

  // Settings
  updateSetting: (key, value) => ipcRenderer.send('update-setting', { key, value })
});
